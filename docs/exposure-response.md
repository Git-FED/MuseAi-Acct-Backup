# Exposure Response

A lockout alone does not prove theft or credential compromise. Treat a credential as exposed when it was displayed in an unintended place, committed to version control, sent to an untrusted recipient, or otherwise accessed outside the intended control boundary.

## Response checklist

- Identify the credential class and issuing provider.
- Revoke or disable the current credential.
- Create a replacement with minimum scope.
- Update the legitimate integration through its secure configuration path.
- Review provider audit logs where available.
- Check for unexpected usage, billing, data access, or permission changes.
- Document facts separately from assumptions.
- If regulated or personal data may be involved, follow the organization's incident and legal-notification process.
